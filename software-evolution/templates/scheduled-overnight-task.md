# Scheduled Overnight Task Prompt

Use `$software-evolution overnight` on the configured local project.

Work autonomously from `effective_config` and repository rules. If the governance control plane is missing, initialize it and continue in the same run. Prefer an isolated worktree. Repeatedly discover, prove, prioritize, repair, test, verify, re-scan, update engineering memory, and checkpoint safe R1/R2 batches while the host remains available and safe verifiable work exists.

Do not stop because of file, finding, cycle, checkpoint, or repair-batch counts. Record those values as telemetry only. A coherent repair may touch many files when its behavior, callers, rollback, and verification are known.

Do not wait for routine confirmation. Record decision-, specialist-, environment-, or approval-blocked items and continue independent safe work. Never deploy, mutate production/shared data, change permissions/credentials/alerts/flags, publish remotely, rewrite Git history, or perform R3/R4 contract/model changes without separate exact authorization.

End with the `RUN-*` ledger, exact tests/results, remaining risks, and the real stop reason. Use explicit `$software-evolution resume <id>` only for host interruption, drift, ambiguity, or targeted recovery; ordinary batch checkpoints continue automatically.
